# read_when 索引

## 0. 一句话

一份长文拆成多份子文档，索引只放「什么问题该读哪份」；读之前先按 `read_when` 命中，然后只读命中的那 1 份。

## 1. 什么时候用 / 不用

用：

- 有一份「必读」背景文档，长到每次都要塞满上下文，而每次任务其实只用其中一两节
- 多个 agent / 多人共用同一套背景说明，需要知道「改这个之前该看哪段」
- 文档还会继续长，需要一开始就定好边界

不用：

- 一次性总结、翻译、改写一篇长文 —— 那是写，不是路由
- 只有几十行、读一遍不痛的文档
- 普通 README：读者需要线性读完，拆分反而更差

## 2. 三个角色

| 角色 | 文件 | 只放什么 |
|---|---|---|
| 索引 | `INDEX.md`（或项目已有主索引） | 路由表、全局总则、最近变更 3~5 条、文档清单 |
| 子文档 | `01-xxx.md` … | 一个主题的正文；开头六字段 frontmatter |
| 契约 | 项目的写入约定（可选，见 `single-writer-shared-data`） | 谁可以改、冲突怎么裁 |

索引**不搬正文**。任何一句话只属于一份文档 —— 在索引里出现一次，就不该在子文档里原样再抄一遍。

## 3. 建索引

frontmatter：

```yaml
---
doc_id: desk-index
title: 桌面工作台索引
scope: 路由与总则；不含任何主题的正文
docs_dir: .
last_updated: 2026-11-23 23:40
---
```

正文骨架：

```markdown
# <标题>

一句话说明这是什么、给谁用。

## 怎么读

1. 先看下面的表，找 `read_when` 命中你这次任务的那一行。
2. 只读那一份。需要第二份时，说明理由再读。
3. 读到的路径、端口、数字，引用时带上子文档名。

## 文档

| 文档 | read_when | 权威 |
|---|---|---|
| [01-启动与服务.md](01-启动与服务.md) | 改端口、加服务、动启动器或自启动时 | 是 |
| [02-维护与排障.md](02-维护与排障.md) | 服务起不来、端口冲突、要备份再改时 | 是 |

## 总则

- 改前备份；改完更新对应子文档与变更记录。
- 冲突时以 `last_updated` 较新者为准。
```

`read_when` 写**任务动词 + 对象**（「改端口」「加服务」「要备份时」），不写文档内容摘要 —— 摘要会诱导 agent 只读索引就下结论。

## 4. 子文档 frontmatter

六字段，缺一个 `check-routing.sh` 就不放行：

```yaml
---
doc_id: desk-startup
title: 启动与服务
scope: 本机服务端口表、启动器、自启动项的登记与修改
read_when: 改端口、新增服务、动启动器或自启动项、排查服务没起来时
authority: self
last_updated: 2026-11-23 23:40
---
```

- `scope` 一句话写清边界，特别是**不包含什么**。
- `read_when` 列具体的触发场景，用顿号/逗号分隔；**禁止**写「任何」「相关」「全部」「all」「any」这类没有判别力的词。
- `authority: self` 表示这份文档就是该主题的权威；指向别处时写相对 `docs_dir` 的路径，且那个文件必须存在。
- `last_updated` 格式必须是 `YYYY-MM-DD HH:MM`，脚本按这个格式校验。

细节见 `references/subdoc-frontmatter.md`。

## 5. 路由：怎么读

1. 先在索引里搜关键词（标题、`read_when`、正文里的专有名词）。
2. 命中 1 份 → 读它。
3. 命中多份 → 按 `read_when` 的贴合度选最贴近的一份；确实需要第二份时，在读之前说清为什么。
4. 都没命中 → 说明要么索引缺路由（补上），要么这事不属于这套文档（去问人）。

**不要**「为了保险全读一遍」—— 那等于没拆。

## 6. 拆一份长文

1. 先通读，把内容切成独立主题（一个主题 = 一个问题域，能被一句话 `scope` 覆盖）。
2. 合并「总是一起被需要」的主题；拆开「总被一起塞进上下文但其实互不相干」的主题。
3. 每个主题写 `scope` 与 `read_when`，先写路由再写正文 —— 写不出 `read_when` 的主题说明边界没想清。
4. 把原文章节按主题搬过去，**原样搬**，不要借机改写（改写留到后面单独做）。
5. 索引写路由表；正文里跨文档的引用改成 `见 03-xxx.md`。
6. 跑 `scripts/check-routing.sh INDEX.md`，全部 `[ok]` 再交付。
7. 原文保留一版归档（或留在 git 历史里），确认新结构可用后再删。

完整判断标准与反模式见 `references/split-playbook.md`。

## 7. 维护

- 改子文档 → 必须更新它的 `last_updated`；改的是别人负责的主题 → 走共享写入协议。
- 新增子文档 → 同一提交里登记进索引，否则 `check-routing.sh` 报「未登记」。
- 索引长大到超过一屏 → 索引本身该再拆（分主题索引），而不是把 `read_when` 写得更长。
- 变更记录放索引底部最近 3~5 条，旧的移进专门的变更文档。

## 8. 检查清单

- [ ] 索引里每个链接都指向存在的文件
- [ ] 磁盘上每个子文档都在索引里登记
- [ ] 六字段齐全，`last_updated` 格式正确
- [ ] `read_when` 是场景，不是内容摘要，不含禁词
- [ ] 索引没有复制正文段落
- [ ] 随机挑一个任务，能靠 `read_when` 唯一定位到一份

## 9. 脚本

```sh
scripts/check-routing.sh INDEX.md              # 默认 docs_dir 取索引 frontmatter
scripts/check-routing.sh INDEX.md --docs-dir ./docs
```

校验：索引链接 ↔ 磁盘文件双向对齐、六字段齐全、`read_when` 可用、`authority` 存在、`last_updated` 格式。退出码 0 = 全部通过，1 = 有失败项。
