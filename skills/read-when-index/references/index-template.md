# 索引模板

## 文件头

```markdown
---
doc_id: <项目>-index
title: <这套文档叫什么>
scope: 路由、总则、最近变更；不含任何主题的正文
docs_dir: .
last_updated: 2026-11-23 23:40
---
```

| 字段 | 说明 |
|---|---|
| `doc_id` | 唯一标识，kebab-case |
| `title` | 人看的标题 |
| `scope` | 这份索引负责什么；明确写「不含正文」 |
| `docs_dir` | 子文档所在目录，相对索引文件；省略 = 索引所在目录 |
| `last_updated` | `YYYY-MM-DD HH:MM`，脚本会校验 |

## 正文

```markdown
# <标题>

一句话：这是什么、给谁用、什么时候该打开它。

## 怎么读

1. 在下表里找 `read_when` 命中你这次任务的那一行。
2. 只读那一份；需要第二份时先说明理由。
3. 引用其中的路径、端口、数字时，带上子文档名，方便别人回查。

## 文档

| 文档 | read_when | 权威 |
|---|---|---|
| [01-启动与服务.md](01-启动与服务.md) | 改端口、加服务、动启动器或自启动项时 | 是 |
| [02-维护与排障.md](02-维护与排障.md) | 服务起不来、端口冲突、要备份再改时 | 是 |
| [03-变更记录.md](03-变更记录.md) | 想知道某个改动是哪次、谁做的时 | 是 |

## 总则

- 改前备份。
- 改完更新对应子文档与变更记录。
- 冲突时以 `last_updated` 较新者为准。

## 最近变更

- 2026-11-23 23:40 · 初版拆分
```

## 硬规则

1. **一列一链接**：索引正文里每个子文档只出现一次，用一个 markdown 链接 `[名](file.md)` 指过去。脚本按这个找。
2. **不搬正文**：索引里不出现「怎么改端口」这类操作步骤，最多写一句总则。
3. **路由表按使用频率排**，常用的在上。
4. **最近变更**最多 5 条，超出就移进 `变更记录` 子文档。
5. 文档清单和磁盘必须双向一致 —— 少了只报「未登记」，多了报「不存在」。

## 索引自己长大了怎么办

超过一屏（约 60 行）时，别继续往里塞：按主题再建一层 `INDEX-服务.md` / `INDEX-资产.md`，顶层索引只留「什么主题去哪个索引」。规则不变，只是多一跳。
