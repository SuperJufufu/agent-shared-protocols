# 子文档 frontmatter

每份子文档开头必须有这六字段。`check-routing.sh` 逐项检查。

```yaml
---
doc_id: desk-startup
title: 启动与服务
scope: 本机服务端口表、启动器、自启动项的登记与修改；不含排障步骤
read_when: 改端口、新增服务、动启动器或自启动项、排查服务没起来时
authority: self
last_updated: 2026-11-23 23:40
---
```

## 逐字段

### doc_id

kebab-case，全局唯一（同一套文档内不许重复）。索引里用得到，日志/引用也用它。

### title

人看的短标题，和索引里那一行的链接文字一致。

### scope

一句话，说清**包含什么**和**不包含什么**。写不出「不包含」通常说明边界没定。

- 好：「本机服务端口表与启动方式；不含排障步骤（见 02）」
- 差：「和桌面有关的一切」

### read_when

**这是路由的核心**。写任务场景，不是内容摘要。

- 好：「改端口、加服务、动启动器或自启动项、要写进变更记录时」
- 差：「服务相关」（太宽，几乎每次都命中）
- 差：「任何需要了解服务的时候」（禁词，永远命中 = 没有路由）

规则：

1. 用「动词 + 对象」：改端口、加服务、迁移数据、排查起不来。
2. 至少写两个具体场景，最多写四五个；再多说明该拆了。
3. 禁词：任何、相关、全部、所有、一切、随便、all、any、everything、`*`。
4. 不复述 scope —— `scope` 说边界，`read_when` 说触发。
5. 不写「详见 …」这类指向别处的路由，路由只属于索引。

### authority

- `self`：这份文档就是该主题的权威，别处不许再抄一份。
- 其他：相对 `docs_dir` 的路径，指向真正权威的那份；文件必须存在。

一份内容只有一个权威。出现「两份都像权威」时，留一份、另一份改成一行指针。

### last_updated

格式 `YYYY-MM-DD HH:MM`（24 小时制，本地时间即可，全库统一）。

- 改内容就更新它，**只改错别字也要更新** —— 它是冲突裁决依据。
- 不写 `2026-11` 或 `今天`，脚本按固定格式校验。
- 精确到分钟够了；不要写秒，避免无意义的差异。

## 常见错法

| 错法 | 后果 |
|---|---|
| frontmatter 用三反引号或缺少 `---` | 脚本读不到，整份被判失败 |
| `read_when` 写「所有关于 X 的内容」 | 路由失效，agent 每次都读它 |
| 同一主题两份文档都写 `authority: self` | 冲突时无从裁决 |
| `last_updated` 忘记更新 | 冲突裁决用到过期时间，错的会赢 |
| `scope` 写成一串功能列表 | 边界看不出来，越写越厚 |
