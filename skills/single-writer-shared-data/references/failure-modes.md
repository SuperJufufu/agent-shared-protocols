# 六种失败模式

每一条都写成「症状 → 根因 → 对策 → 怎么发现」。前三条会静默丢数据，后三条会让人误以为安全。

## 1. 整文件覆盖

- **症状**：别人的改动凭空消失；`git diff` 里出现一大片「没动过」的行。
- **根因**：读入全文 → 改一处 → 写回全文。中间别人写的那次被当成基线。
- **对策**：改节不改全文；写入前必须有 pre-copy；只允许 `mv` 临时文件覆盖，不许 `>` 直接截断重写。
- **怎么发现**：`verify-readback.sh --pre-copy` 报出「改到了声明之外的节」。

## 2. 建议性认领交错

- **症状**：两人都通过了 `check`，都写了，结果一人的改动丢了半节。
- **根因**：`check` 与写入之间有窗口；文件系统不提供原子「检查并占用」。
- **对策**：把窗口压到最短（认领后立刻写）；写入用小节替换而不是整文件；写完回读；冲突按 freshness 合并。**接受**偶发交错，但保证它可被发现、可合并。
- **怎么发现**：回读时发现差异超出声明节；或 freshness 被对方改过。

## 3. 孤儿认领

- **症状**：某节永远显示「被占」，实际没人在写；所有人都在等。
- **根因**：agent 崩溃 / 会话结束，没有 `release`。
- **对策**：TTL + `reap`；回收时在 note 写明「回收 <agent> 的过期认领」；长时间任务用续期而不是超长 TTL。
- **怎么发现**：`claim.sh list` 里 `expires` 已过。

## 4. 只追加文件被改

- **症状**：历史少了行、顺序变了、措辞被"顺手修正"。
- **根因**：把 changelog 当普通文档编辑。
- **对策**：只追加文件只允许在顶部/尾部加行；校验旧行数只增不减。
- **怎么发现**：`wc -l` 变小；或对旧内容取 hash 后比对。

## 5. 回读只看「文件还在」

- **症状**：回读通过，但结构坏了（frontmatter 断裂、标题重复）或别的节被覆盖。
- **根因**：把「能打开」当成「写对了」。
- **对策**：回读要检查结构（frontmatter 成对、标题唯一）+ 用 pre-copy 差分确认改动范围。
- **怎么发现**：`verify-readback.sh` 的结构检查项。

## 6. 把 mtime 当锁

- **症状**：两个人同时判断「文件没变」，同时开写。
- **根因**：`mtime` 只表示"最近被写过"，不表示"谁在写"。
- **对策**：用认领表表达意图，`mtime` 最多用来判断"是否需要重读"。
- **怎么发现**：冲突后回看，两边都认为自己是基于最新版本改的。

---

**共同点**：这些都发生在"看起来一切正常"的时候。所以协议里每一步都要有一个**能失败的检查** —— 认领有退出码、回读有差分、只追加有行数。没有检查的步骤等于没有这一步。
