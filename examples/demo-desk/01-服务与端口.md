# 服务与端口

## 权威在哪

端口与服务的事实只写在 `shared/state.md`。这份文档讲**怎么改**，不重复端口表 —— 重复一份就等于制造第二权威。

## 改一个端口

1. 读 `shared/CONTRACT.md`，确认 `## 端口` 是可写节。
2. 认领：

   ```sh
   scripts/claim.sh claim shared/CONTRACT.md 'shared/state.md#端口' \
     --agent dsh --ttl 30 --note '把 8080 换成 8090'
   ```

   退出码 4 就是有人占着，等或换时间，不要硬抢。

3. 备份 → 只改 `## 端口` 节 → `mv` 临时文件覆盖。
4. 回读：

   ```sh
   scripts/verify-readback.sh shared/state.md \
     --pre-copy /tmp/state.md.pre.$$ --section '## 端口'
   ```

5. 追加一条 `shared/changelog.md`，再 `release` 认领。

## 加一个服务

- 端口从 `## 端口` 的空位里挑，不占别人已登记的。
- 启动命令写进 `## 服务`，一条一行，带上工作目录。
- 自启动项登记在 `02-备份与恢复.md` 的「改前检查」里也要提一句，因为自启动失败通常表现为"重启后服务没了"。

## 排障顺序

1. 端口有没有被占：`ss -ltnp | grep <port>`
2. 进程在不在、日志最后 20 行写了什么
3. 自启动项是否还指向存在的路径
4. 以上都正常 → 说明是改动没生效，回去看 `verify-readback.sh` 的输出
